# Render course-pilot deployment

This guide describes the React, Spring Boot and PostgreSQL deployment defined in `render.yaml`.

## Create the services

1. Connect your GitHub account in the Render Dashboard and select this repository when creating a Blueprint.
2. Use the root `render.yaml`. Review the listed plans and Render's current terms before creating services.
3. Provide the variables below. The Blueprint links its own database and generates its own JWT secret.
4. Use the actual URLs shown by Render after creation. The Blueprint's service names may already be taken in another workspace.

## API environment

| Variable | Value |
| --- | --- |
| `ADMIN_EMAIL` | Email-shaped identifier for your coordinator account |
| `ADMIN_PASSWORD` | New 12–72 character ASCII password for the initial coordinator |
| `CORS_ALLOWED_ORIGINS` | Actual frontend HTTPS origin, without a trailing slash or path |
| `RENDER_DATABASE_CONNECTION` | Supplied by the Blueprint from its own PostgreSQL database |
| `JWT_SECRET` | Generated by the Blueprint |
| `SEED_DEMO` | `false` in the hosted course pilot |
| `REPORT_PHOTOS_ENABLED` | `true` |

The Blueprint sets the API bind address, port and Java memory options. Its health check is `/api/drains`. Bootstrap creates an administrator when the configured email is absent. Existing accounts retain their stored password and role across deployments.

## Frontend environment

| Variable | Value |
| --- | --- |
| `REACT_APP_API_URL` | Actual API HTTPS origin, without a trailing slash or path |
| `REACT_APP_GOOGLE_MAPS_API_KEY` | Your browser key with Maps JavaScript API enabled |
| `REACT_APP_GOOGLE_MAPS_MAP_ID` | Optional project map ID |
| `REACT_APP_COURSE_PILOT` | `true` |
| `DISABLE_ESLINT_PLUGIN` | `true`, matching the inherited build configuration |

The Blueprint uses Node.js 24.22.1 and pnpm 11.25.0. Restrict a standard Maps browser key to the website origins using it, including the actual frontend domain. Frontend variables are embedded during the build, so deploy a fresh build after changing them.

## Update an existing deployment

Automatic deploy triggers are set to `off` in this Blueprint. Select the required commit and manually deploy the API first, followed by the frontend when both changed. Documentation-only changes can be pushed independently of an application deployment.

## Check the result

Open the HTTPS website on another device and verify the homepage, map, direct navigation to `/drains`, registration and sign-in. Using demonstration data, check account-free reporting, the private link, coordinator feedback, public-location publishing and shared adoption.

Current public photos, private photos, reports, public locations and shared adoptions are stored in PostgreSQL. Legacy report-photo records may still reference the API's local filesystem. The free-service filesystem is ephemeral, so plan migration or persistent storage for legacy records if needed.

Private reports accept one JPG/PNG up to 5 MB. The stored photo is stripped of image metadata and normalized to a JPEG of at most 512 KiB. A 128 MiB total private-photo allowance applies. The administrator or private-link holder can access a report photo. Anonymous CSV export omits photos, descriptions, precise locations and tracking credentials.

## Service limits and data retention

Use test data for the course trial and record the database expiry date shown in the Dashboard. Render's free API can spin down when idle, and free PostgreSQL databases currently expire after 30 days. Arrange an export or a suitable plan before expiry if records need to be kept. The database holds photos and adoption records as well as reports.
